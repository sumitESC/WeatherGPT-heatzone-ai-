# WeatherGPT Backend (HeatZone ML Server)

> **Module Role in WeatherGPT**: The core computational engine for WeatherGPT. It is responsible for serving the multi-horizon numerical forecasts generated by the custom **Temporal Fusion Transformer (TFT)** model, alongside data ingestion, heat risk scoring, and serving meteorological intelligence via RESTful APIs to the conversational edge and dashboards.

---

## 1. Abstract

The `heatzone-backend` is a FastAPI-based server that powers the numerical pipeline of the WeatherGPT ecosystem. It serves 30-day (720-hour) multi-variable forecasts generated by our **~15M parameter Temporal Fusion Transformer (TFT)** model. The model was trained on a massive 5GB dataset comprising **26 years of hourly ERA5 reanalysis data**, Sentinel-2 satellite imagery, and terrain features. The backend also runs a Random Forest heatwave predictor to produce heat risk scores (0-100) and executes real-time data ingestion pipelines from Open-Meteo and Sentinel-2 APIs for 75+ cities across Uttar Pradesh, India.

## 3. Core Forecasting Engine (TFT)

The backend's primary forecasting engine is a **Temporal Fusion Transformer** originally trained via Google Colab (`D:\code\weatherGPT\Colab_Training\`).

### 3.1 TFT Model Specifications

| Specification             | Value                                              |
|---------------------------|----------------------------------------------------|
| **Architecture**          | Temporal Fusion Transformer (TFT)                  |
| **Trainable Parameters**  | ~15M+                                              |
| **Lookback Window**       | 168 hours (7 days)                                 |
| **Forecast Horizon**      | 720 hours (30 days)                                |
| **Input Features**        | 59 Weather + 13 Satellite/Terrain + 6 Cyclic Temporal |
| **Target Variables**      | 35 variables × 720 timesteps                       |
| **d_model**               | 128 (local) / 192 (Colab)                          |
| **Attention Heads**       | 4 (local) / 6 (Colab)                              |
| **Loss Function**         | Quantile Pinball (for probabilistic bounds)        |

### 3.2 Feature Composition (78 Features)

- **Weather Variables (59)**: Sourced from Open-Meteo (Temperature, Humidity, Wind, Pressure, Radiation, Soil Moisture, etc.)
- **Satellite & Terrain (13)**: Sentinel-2 L2A indices (NDVI, NDWI, NDBI, SAVI, BSI, Albedo) and Copernicus DEM Elevation.
- **Cyclic Temporal (6)**: Sine/cosine transformations for hour-of-day, day-of-year, and month-of-year.

### 3.3 Prediction Targets (35 Variables)

The inference pipeline generates 30-day forecasts for:
- **Thermal**: Temperature, Dewpoint, Apparent Temp, Wet Bulb.
- **Hydrological**: Humidity, Precipitation, Rain Prob, ET₀, VPD.
- **Pressure & Wind**: MSL Pressure, Wind Speed (10m, 80m), Wind Direction, Gusts.
- **Solar & Storm**: Shortwave Radiation, UV Index, CAPE.

## 4. Heatwave Prediction Model (Heat Risk)

Alongside the TFT model, the backend calculates a proprietary **Heat Risk Score (0-100)** using a Random Forest + Gradient Boosting ensemble.

| Specification             | Value                                        |
|---------------------------|----------------------------------------------|
| **Algorithm**             | VotingRegressor (GradientBoosting + RandomForest) |
| **Input Features**        | 19 (NDVI, NDWI, NDBI, emissions, LST, etc.)  |
| **Validation R²**         | 0.9771                                       |
| **Output**                | Heat Risk Score + Zone (🟢🟡🟠🔴) + Causal Explanation |

**Heat Risk Scoring Algorithm**:
The score is a composite of multiple factors: Temperature, Built-Up density (NDBI), Emission index, Population density, lack of Green cover (Penalty), Land Surface Temperature (MODIS), and Urban Nightlight Glow (VIIRS).

## 7. Setup & Deployment

### Local Development
```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python server.py
```
- **Swagger Docs**: `http://localhost:8000/docs`

### Production (Render.com)
The backend is configured to auto-deploy via `render.yaml`. It runs background tasks to periodically fetch the latest 168-hour historical lookback data to feed into the TFT model for continuous 30-day forecast generation.
